# 2\. Use Case Specification

# 1. UC — eWay 360° Performance Review

## 1.1. Use Case Overview

Ovations Technologies conducts **semi-annual 360° performance reviews** aligned to the company's **"eWay"** values and competencies. The application must allow employees to nominate peers, submit ratings against eWay criteria, provide qualitative feedback, and generate aggregated results.

**Application Name:** eWay 360° Review  
**Purpose:** Internal semi-annual 360° performance reviews  
**Users:** All Ovations employees, managers, and HR/Admin  
**Review Frequency:** Semi-annual (twice per year)

## 1.2 Key Concepts

| Concept | Description |
| --- | --- |
| **eWay Criteria** | Predetermined competencies/values that form the rating dimensions. These are configured by Admin/HR and apply company-wide per review cycle. |
| **360° Review** | An employee is rated by multiple people: their manager (mandatory), peers they nominate, and peers who nominate them. |
| **Nomination** | An employee selects who they want to rate them (inbound) and who they want to rate (outbound). The direct manager is **auto-included and cannot be removed**. |
| **Rating** | A numeric score (1–5) per eWay criterion, plus two comment fields. |
| **Aggregation** | All ratings for an employee are averaged per criterion and overall to produce a final score. |
| **Comments** | Each reviewer provides: **"What they do well"** and **"What they need to improve"**. |
| **Direct Reports** | The list of employees reporting to a specific Line Manager where that Line Manager is configured in the system for that Employee. |

##   
1.3 eWay Criteria sections and questions

- Each question’s answer need to be recorded separately
- The decimal average (rounded to only 2 decimals) of the questions for each section need to be calculated and stored as the result on that criterion section. 
- The last section has three additional questions
- **Rating Scale to use:** 1 = Needs Significant Improvement · 2 = Needs Improvement · 3 = Meets Expectations · 4 = Exceeds Expectations · 5 = Exceptional

| eWay Element | Questions per Element |
| --- | --- |
| ***MASTERFUL***(Rating Scale selection 1 to 5) | 1. Invests in the Development of others 2. Displays evidence of Continuous Learning to enhance role expertise 3. Uses innovative approaches to solve problems 4. Displays the neccesary focus on attention to detail 5. Takes time to think about challenging tasks and what could have been done better |
| ***EXCELLENCE***(Rating Scale selection 1 to 5) | 1. Inspires others & leads by example 1. Displays Client centric behaviour by striving to deliver client outcomes 1. Consistently delivers Quality outcomes 1. Always delivers promised commitments on time 1. Displays excellent verbal and written communication skills |
| ***EXECUTION***(Rating Scale selection 1 to 5) | 1. Delivers outputs efficiently and effectively 1. Is reliable and disciplined 1. Plans tasks well before executing, adjusts as needed 1. Handles multiple demands, prioritises work and communicates any changes 1. Takes ownership and delivers on the expected outcomes |
| ***COMMITMENT***(Rating Scale selection 1 to 5) | 1. Punctual and Engaged in all interactions 1. Takes Accountability for actions 1. Proactive and takes Initiative to accurately complete project and Ovations deliverables on time 1. Loyal to Ovations 1. Displays courage with a can-do attitude and a strong work ethic |
| ***CONTRIBUTION***(Rating Scale selection 1 to 5) | 1. Contributes to knowledge management activities relevant to level and role 1. Committed to an environment of Teamwork and Collaboration 1. Is Positive and Embraces Diversity 1. Contributes to the Ovations Financial and Sales Outcomes 1. Acknowledges others effort and achievements |
| ***ADDITIONAL QUESTIONS***(Multiline text boxes, Yes/No) | 1. What should this person pay attention to? \[TEXT\] 2. What is this person doing well? \[TEXT\] 3. If you have a challenging project or assignment, would you want this person on your Team? \[YES/NO\] |


# 2. System Roles & Permissions (RBAC)

| Role | Permissions |
| --- | --- |
| **HR Administrator** | - Manage employee list (add / edit / deactivate employees) - Set manager relationships and reporting structure - Create, open, and close review cycles - View combined results and reports - Manage reviews (Override/ Cancel / Edit / Unlock) as needed - ***OPTIONAL***: Configure eWay criteria (add / edit / deactivate) - HR Administrator **is also an Employee **role to be reviewed |
| **Line Manager** | - Auto-included as reviewer for all direct reports - Review and approve nomination suggestions for their direct reports - View aggregated results for their direct reports once the nominees have concluded the rating for that employee - Cannot see individual reviewer identities (anonymised peer reviews) - Line Manager **is also an Employee **role to be reviewed and can review others |
| **Employee** | - Nominate peers to rate them (reviewed by) - Nominate peers they want to rate (reviewer for) - Complete own and peer reviews (submit ratings and comments) for nominated employees - View own aggregated results (after cycle closes) - Cannot see individual reviewer identities |

#   
3. Review Cycle Workflow

Each review cycle follows a lifecycle below:

| **Step #** | **Status** | **Description** | **Who** |
| --- | --- | --- | --- |
| **1** | DRAFT | Admin creates a new review cycle, sets dates, selects active eWay criteria | **HR Administrator** |
| **2** | NOMINATE | Employees select who they want to rate them and who they want to rate. Manager is auto-added and locked. Min/max nomination limits enforced. | **Employee** |
| **3** | APPROVE | Manager/HR reviews and approves nominations for their team | **Line Manager** |
| **4** | REVIEW | Reviewers rate each nominated employee on all eWay criteria (1–5) and provide two comments: "What they do well" and "What they need to improve" | **Employee** |
| **5** | CALCULATION | System calculates averages per criterion and overall. Comments are compiled anonymously. | **System** |
| **6** | CONSULTATION | Manager reviews results for direct reports. Comments shown without reviewer names. | **Line Manager** |
| **7** | ACCEPT | Employee can view and accept own results. | **Employee** |
| **8** | CLOSED | Admin closes cycle. Results become read-only historical record. | **HR Administrator** |

4. MVP 1 — Essential Requirements

***MVP 1************Is the minimum viable product all teams must try and deliver to produce a working solution.*

## 4.1 Authentication & User Management

| **ID** | **Requirement** | **Acceptance Criteria** |
| --- | --- | --- |
| **REQ-AUTH-01** | User login with email and password (Office 365 login) | User can log in; invalid credentials show error; session persists until logout. System should not save passwords in the database. |
| **REQ-AUTH-02** | Role-based access (**HR Administrator**, **Line Manager**, **Employee**) | Each role sees only permitted screens and data; unauthorised access blocked |
| **REQ-AUTH-03** | **HR Administrator **can manage the list of employees and their roles | Admin can add, edit, deactivate employees; set name, email, department, manager |
| **REQ-AUTH-04** | **HR Administrator **can set the Line Manager for each employee | Each employee has exactly one direct manager; manager auto-included in reviews |
| **REQ-AUTH-05** | **HR Administrator **should be configured at first startup in order to create the initial list of employees. | Application starts with at least one HR Admin for initial startup purposes. |

##   
4.2 Review Cycle Management

| ID | Requirement | Acceptance Criteria |
| --- | --- | --- |
| **REQ-CYC-01** | Admin can create a new review cycle | Cycle created with name (e.g., "H1 2026"), start/end dates, and selected eWay criteria |
| **REQ-CYC-02** | Admin can open a cycle for nominations | Status transitions Draft → Nomination; employees can begin nominating |
| **REQ-CYC-03** | Admin can advance cycle through phases | Admin can move cycle: Nomination → Approval → Review → Calculation → Results → Closed |
| **REQ-CYC-04** | Only one cycle active at a time | System prevents opening a new cycle if one is already in progress |
| **REQ-CYC-05** | Cycle dashboard shows progress stats | Admin sees: total employees, nominations submitted %, reviews completed %, current phase |

##   
4.3 Nomination of reviewers

| ID | Requirement | Acceptance Criteria |
| --- | --- | --- |
| **REQ-NOM-01** | Employee can nominate peers to rate them (inbound reviewers) | Employee selects from employee directory; selected peers will review them |
| **REQ-NOM-02** | Employee can nominate peers they want to rate (outbound reviews) | Employee selects peers they will provide a review for |
| **REQ-NOM-03** | Manager is auto-included as reviewer | Direct manager appears pre-selected and **cannot be removed** from the reviewer list |
| **REQ-NOM-04** | Minimum and maximum nomination limits | Configurable min (e.g., 3) and max (e.g., 8) reviewers per employee; enforced on submit |
| **REQ-NOM-05** | Employee can save draft nominations | Nominations can be saved as draft and submitted later within the nomination window |
| **REQ-NOM-06** | Nomination summary visible to employee | Employee can see: who they've nominated to review them, who they've nominated to review, and pending/submitted status |

##   
4.4 Approval of nominated reviewers

| ID | Requirement | Acceptance Criteria |
| --- | --- | --- |
| **REQ-APR-01** | Manager can review nominations for direct reports | Manager sees nomination list for each direct report with approve/reject per nominee |
| **REQ-APR-02** | Manager can approve or reject individual nominations | Rejected nominations removed; employee notified; minimum threshold re-enforced |
| **REQ-APR-03** | Admin/HR can override approvals | Admin can approve any nomination regardless of manager decision |

##   
4.5 Employee Review & Rating

| ID | Requirement | Acceptance Criteria |
| --- | --- | --- |
| **REQ-REV-01** | Reviewer sees list of people they need to review | Dashboard shows pending reviews with name, department, and completion status |
| **REQ-REV-02** | Reviewer rates employee on each eWay criterion (1–5) | All active criteria displayed; each requires a 1–5 rating; no partial submissions |
| **REQ-REV-03** | Reviewer provides comment: "What they do well" | Free-text field; minimum 20 characters; saved with the review |
| **REQ-REV-04** | Reviewer provides comment: "What they need to improve" | Free-text field; minimum 20 characters; saved with the review |
| **REQ-REV-05** | Reviewer can save draft and submit later | Draft reviews saved; only submitted reviews count toward calculation |
| **REQ-REV-06** | Submitted reviews are locked | Once submitted, reviewer cannot edit their review |
| **REQ-REV-07** | Review form validates all fields before submission | All criteria rated + both comments filled → submit enabled; otherwise show validation errors |

##   
4.6 Score Calculation & Aggregated Results

| ID | Requirement | Acceptance Criteria |
| --- | --- | --- |
| **REQ-CALC-01** | System calculates average rating per criterion per employee | Average of all reviewer scores for each criterion; displayed to 2 decimal places |
| **REQ-CALC-02** | System calculates overall average score per employee | Average across all criteria averages; single overall score displayed |
| **REQ-CALC-03** | Number of reviewers shown (not identities) | Results page shows "Based on X reviews" without revealing reviewer names |
| **REQ-CALC-04** | Comments displayed anonymously | "What they do well" and "What they need to improve" listed without attribution |
| **REQ-CALC-05** | Employee can view own results after cycle reaches Results phase | Employee sees: per-criterion averages, overall score, anonymised comments |
| **REQ-CALC-06** | Manager can view results for direct reports | Manager sees aggregated results for each direct report |
| **REQ-CALC-07** | Admin/HR can view all employee results | Admin can filter by department, sort by score, and view any employee's results |

4.7 Dashboard & Navigation

# 7. Data Model

Suggested entities — teams may adapt the schema to their stack:

| Entity | Key Fields | Relationships |
| --- | --- | --- |
| **Employee** | id, name, email, department, role (Admin/Manager/Employee), managerId, isActive | belongs to Department; has one Manager (self-ref) |
| **Department** | id, name, description | has many Employees |
| **ReviewCycle** | id, name, startDate, endDate, phase (enum), createdBy | has many eWayCriteria (selected); has many Nominations |
| **EwayCriterion** | id, name, description, isActive, sortOrder | used in ReviewCycles; rated in ReviewRatings |
| **Nomination** | id, cycleId, employeeId, reviewerId, direction (inbound/outbound), status (pending/approved/rejected) | belongs to ReviewCycle, Employee (subject), Employee (reviewer) |
| **Review** | id, cycleId, reviewerId, employeeId, doWellComment, improveComment, status (draft/submitted), submittedAt | belongs to ReviewCycle; has many ReviewRatings |
| **ReviewRating** | id, reviewId, criterionId, score (1–5) | belongs to Review and EwayCriterion |
| **ReviewResult** | id, cycleId, employeeId, criterionId, avgScore, reviewCount | calculated aggregate; belongs to ReviewCycle, Employee, EwayCriterion |

# 8. Human-in-the-Loop (HITL) Requirements

**Mandatory:** Each team must document at least **3 Human-in-the-Loop interventions** where a human developer reviewed, corrected, or enhanced AI-generated output.

## 8.1 HITL Intervention Types

| Type | Description | Example |
| --- | --- | --- |
| **Code Review** | Developer reviews and corrects AI-generated code | Fixing incorrect score calculation logic |
| **Architecture Decision** | Human overrides AI's architectural suggestion | Choosing a different DB schema for nominations |
| **Security Review** | Human identifies and fixes security issues in AI code | Adding input validation to prevent XSS in comments |
| **UX / Design Override** | Human redesigns AI-generated UI for better usability | Restructuring the review form layout |
| **Prompt Engineering** | Iterative refinement of prompts to improve AI output | Refining the prompt for score calculation logic 3 times |
| **Business Logic Correction** | Human corrects AI's misunderstanding of business rules | Ensuring manager is locked in nominations and cannot be removed |
| **Testing & QA** | Human writes or corrects test cases beyond AI output | Adding edge case tests for boundary scores (1 and 5) |
